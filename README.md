# 電腦 / 端點身分驗證特徵總覽（Device & Behavioral Feature Catalog）

> 給 VAKTEN 的對照用。分成三部分：
> 1. 官方分級框架（金管會指引 / 金融 FIDO）— 這是「方法論」，不是特徵清單
> 2. 裝置指紋 + 行為特徵欄位（130+ 項）— 這才是「一百多種特徵」的來源
> 3. 標注：端點層可取得 vs Web 層專屬，以及對應 VAKTEN 三層引擎的建議
>
> 標記說明：`[端]` = Windows 端點可直接取得；`[Web]` = 瀏覽器/JS 環境專屬；`[端+Web]` = 兩者皆可

## Part 1 ─ 官方框架（不是特徵，是分級方法論）

| 文件 | 發布單位 | 性質 |
|---|---|---|
| 金融服務業辦理數位身分驗證指引 (2023) | 金管會 | 風險基礎分級（參考 ISO/IEC 29115）：風險 低/中/高/極高；信賴等級 1~4 |
| 金融機構辦理快速身分識別機制安全控管作業指引 | 金管會 | 金融 FIDO：IDP / RP / 身分核驗者角色與作業環境要求 |
| 金融機構辦理電子銀行業務安全控管作業基準 | 金管會 | 依上述指引改版，框定各業務適配的驗證機制 |

**驗證因子三分法（傳統）**
- 所知（something you know）：密碼、PIN、安全問題
- 所持（something you have）：OTP 載具、IC 卡、憑證、綁定裝置
- 所是（something you are）：生物特徵（指紋、臉、虹膜、行為）

> 裝置指紋 / 行為特徵屬於「隱形因子（passive / risk-based）」，通常疊在上面三類之上做**持續性驗證（continuous authentication）** — 這正是 VAKTEN 的定位。

## Part 3 ─ 對應 VAKTEN 三層引擎的建議

| 你的層 | 適合吃哪些特徵 | 說明 |
|---|---|---|
| **規則層** | A/B/E/I 的穩定硬體/環境/姿態特徵 | 硬性條件：未知裝置、VM、缺加密、IP 黑名單 → 直接扣分或阻擋 |
| **AI 層** | G/H 的連續數值特徵 | 行為節律、稀有度、impossible travel → 異常分數（你 f9、晝夜先驗都在這） |
| **語意層（LLM）** | 跨層事件序列的「敘事」 | 把上面各層的異常組成一段事件描述，讓輕量 LLM 判斷「這串行為合不合理」— 這正是你論文想擴的方向 |

### 給論文的實務提醒
- **公開資料集**（你不能用公司資料）：keystroke 可看 **CMU Keystroke Dynamics Benchmark**、**Buffalo/Clarkson**；滑鼠行為看 **Balabit Mouse Dynamics Challenge**；UEBA/入侵看 **CERT Insider Threat**、**LANL Auth**、**CIC-IDS2017**。
- **鑑別度 vs 穩定度取捨**：Canvas/WebGL/字型鑑別度高但會隨更新漂移；硬體序號穩定但端點才拿得到。VAKTEN 是端點程式，優先吃 `[端]` 類，別過度依賴 `[Web]` 指紋。
- **MAC / IP 已被隨機化**：現代 OS 會隨機化 MAC、行動網路動態 IP，權重要調低，改靠組合特徵。
- **隱私 / 合規**：對到金管會指引時，這些特徵屬「風險基礎的隱形因子」，蒐集要在個資告知範圍內（指引也要求告知客戶可撤回同意）。
